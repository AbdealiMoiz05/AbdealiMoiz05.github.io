# Order-to-cash exception monitor

A personal project on **synthetic data**. It finds late deliveries, overdue unpaid invoices and disputes across 8 vehicle-maker customers.

No real company data is used. Every record is generated by `generate_data.py`.

## What it does
- `generate_data.py` creates 3,000 orders, deliveries, invoices and payments as CSV files.
- `load_and_flag.py` loads the CSVs into SQLite and runs the exception rules in `schema.sql`.
- `schema.sql` holds three SQL queries: late deliveries, overdue unpaid invoices, and disputes by customer.

## Run it
```
python3 generate_data.py
python3 load_and_flag.py
```
Python 3 only. No extra packages.

## Known limits
- A delivery one day after the promise counts as late. Tighten the rule if you want a grace period.
- The overdue query uses a fixed cut-off date of 31 December 2026. Change it for other periods.
- The data is random, so the numbers show the method, not real performance.
